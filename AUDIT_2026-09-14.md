# Reviewer audit of the barley NIR repository

The public GitHub archive supports the reported computational results. Independent calculations reproduced the saved metrics, all five scientific manuscript tables and the complete paired bootstrap draw sequence. Fresh selected outer fits reproduced the saved predictions for all three model families in fold 1. Four execution or documentation issues were corrected. No unresolved blocking computational defect was identified within these checks. The study still has substantive experimental limitations, and this audit does not establish external biological validity.

Repository examined: [Julians30/barley-nir-stage-benchmark](https://github.com/Julians30/barley-nir-stage-benchmark). Audit baseline: `9c998bd2ec5e3bbe1119e8247bdcbf6e9cbf1d2e`. Evidence: [AUDIT_EVIDENCE_2026-09-14.json](AUDIT_EVIDENCE_2026-09-14.json). The audit was performed through code execution and inspection using AI assistance; it is not an independent human peer-review certificate.

## Limits that remain

The principal limitation is stage–session confounding: dishes are held out, but acquisition occasions are shared between training and test. Computational reproducibility cannot establish whether the signal reflects exposure progress, session conditions or both. Independent sequences with stage and session separated are required for that question.

The lower aggregate MAE includes an easy dry reference. Post-moisture MAE 0.680 and R² 0.618 appropriately qualify aggregate MAE 0.577 and R² 0.781. The partition difference of about 0.021 is descriptive, not a statistical equivalence test or a causal measure of leakage. Bootstrap intervals are conditional on fixed OOF predictions. Prior same-data feasibility choices and family-level exploratory transfer checks remain disclosed. PLS profiles do not directly explain nonlinear SVR or validate chemical moisture concentration.

This audit repeated three selected outer fits and two training-only PLS diagnostic fits in one fold; it did not rerun the full nested tuning grid or an end-to-end full fresh project. Fresh-project preparation and failure controls were tested. The optional refit command requires additional computation and is not run by default in GitHub Actions.

Data notices and CC BY-NC 4.0 remain distributed. No separate software license is confirmed, so public access should not be presented as an independently approved open-source license. Bibliographic content was checked for internal consistency; a new complete external reference verification and venue-specific submission/declaration review were not performed. Historical review templates concern earlier drafts; this report and `REPOSITORY_STATUS.json` describe current GitHub readiness. No archival service was used.

## Repeat the audit

From the repository root, with Python 3.12 and the recorded dependencies installed:

```bash
python tools/verify_repository.py
```

For selected-fold fresh fits and an optional original-subset comparison:

```bash
python tools/audit_reviewer_readiness.py --refit-fold 1 --output ../new-audit.json
python tools/audit_reviewer_readiness.py --source-zip /path/to/original-subset.zip --output ../source-audit.json
```

Use output paths outside this archive to preserve the distributed evidence file. The independent script does not import the primary metric or bootstrap functions. Its optional fresh refits use the released estimator builders. See [REPRODUCIBILITY.md](REPRODUCIBILITY.md) for full fresh-fitting instructions.
